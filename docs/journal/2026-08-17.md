## 15:40 — full 하드닝(`--vm-commercial --m8`) 패킹한 snaky.exe "단독 복구" 재검증

위 v3.3.1 리디자인에서 **가장 강한 옵션으로 패킹**했을 때 여전히 "exe 단독 복구"가 되는지 재확인.
위 실험은 `-l 3 -a --vm --vm-oep`(commercial/m8 없음)였고, 이 경우 `solve_vault_recoverable.py`가 정적으로 플래그 복구 성공.
이번엔 `btg-packer.exe -i input.exe -o snaky.exe -l 3 -a --vm --vm-oep --vm-commercial --m8` (703,488B)로 수행.

결과(핵심):
- CIPHER[41] @0x14fb0, ADD 테이블 @0x15012 는 여전히 `.rdata` 평문(데이터 섹션 미암호화).
- 키스트림 알고리즘 + KS_MUL/KS_ADD 가 `.textb`(0x3a5e6/0x3a5f7)에 네이티브 핸들러로 누출.
- **그러나 시드 `KS0`(0x243F6A8885A308D3)은 파일에 없음** → 이전 `solve_vault_recoverable.py` 방식(전체 41B 윈도우 역변환)은 **더 이상 정적으로 동작하지 않음**.
  - 이유: commercial+m8에서 KS0가 at-rest 암호화된 VM 바이트코드 내부로 이동. 접두사 `BTG3{`만으론 64비트 시드 복구 불가.
- 동적(cdb): 안티디버그가 디버거 감지 시 엔트리(0x46d00)+0x45 `ud2` 트랩(0xC000001D). BP 삽입도 Win32 err 299 차단.
- 결론: full 하드닝에서는 **정적 단독 복구 불가, 동적은 안티디버그+VM 우회 필요**. π/Blowfish 상수 인지 시 정적 가능(설계 약점). 분기 패치는 granted 문자열만.
