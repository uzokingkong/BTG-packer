# 2026-08-16 — btg_vault v3.3 (hardened) 정확한 풀이법 규명

## 요청
- btg_vault v3.3 (hardened) 가 "안 풀린다"고 알려졌으나, 사용자는 "타인은 패킹된 exe
  만으로 푼다"고 주장. 패킹 exe 만으로의 **정확한/구체적 풀이법**을 규명 요청.

## 조치 (ujiwo-zyris-code 노드)
- 소스 전체 열람: `build.rs`, `src/{main,verifier,state,vm,bridge,opaque}.rs`,
  `target/release/build/*/out/generated.rs` (TARGETS 8개 u64).
- 바이너리 전수 검색: 3개 패킹 exe + 원본 `btg_vault_v3.exe`/`f.exe` +
  `build-script-build.exe` 에서
  `FLAG_XOR` 테이블 / 평문 플래그 / `BTG3{` / `stateful` / 단일바이트 XOR 로 검색.
- 런타임 검증: 패킹 exe 3종을 정답/오답으로 실행.

## 핵심 발견
1. **플래그는 패킹 exe에 없다.** `FLAG_XOR` 테이블은 `build.rs`에만 존재하며,
   `build-script-build.exe` 파일 오프셋 **`0x1D456`**에 그대로 존재(검증).
   배포된 crackme(`btg_vault_v3.exe`/`f.exe`) 및 3개 패킹 exe에는 없음.
2. 검증 파이프라인은 **일방향 해시**: 41바이트 입력 → permute → transform →
   region(FNV류) 4개 → bridge/gate → VM 2회 → second_bridge → 8개 u64 → TARGETS 비교.
   → TARGETS에서 플래그 역산(z3/전수조사) 불가.
3. 그래서 "패킹 exe 만으로 정확한 플래그 문자열"을 얻는 것은 구조적으로 불가능.
   실제 풀이 = (1) 빌드 산출물에서 `FLAG_XOR^0xBA` 복원, 또는 (2) 판정 패치.
