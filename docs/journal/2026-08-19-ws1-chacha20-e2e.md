## 요약

`--crypto-mode chacha20`가 **평문 bulk at-rest 경로**에서 실제로 활성화되어, packed
exe가 원본과 **바이트 단위 동일한 출력**(1460 bytes, SHA-256
`4366e2530f32a088306efe497d1762e5a087c54ac6c114b44f3ee13d422dcfe5`, exit 0)을
재현함을 확인했다.

## gate 분석

`src/pipeline/crypto/mod.rs`의 `chacha_mode` 게이트:

```rust
let chacha_mode = ctx.crypto_mode == CryptoMode::ChaCha20
    && !chained_effective && !reencrypt && !vm_oep_effective && !vm_effective;
```

- chacha20은 **평문 bulk at-rest 경로 전용**.
- `--chained-crypto` / `--dispatcher-reencrypt` / `--m7` / `--vm` / `--vm-oep` /
  `--vm-commercial` 조합에서는 RC4/BTG-C1 서브루틴으로 폴백
  (`[!] --crypto-mode chacha20 ignored for this mode: ... falls back to RC4/BTG-C1`).
- 따라서 chacha를 실제로 걸려면 **그 어떤 VM/재암호화/체이닝 플래그도 없이** 평문
  bulk 경로(`--crypto-mode chacha20` 단독 + 기본 crypto)를 써야 한다. `-l 3`(기본)은
  유효.
- **열린 항목 없음** — 요구된 gate(평문 bulk 경로 + lib tests green)를 만족.
