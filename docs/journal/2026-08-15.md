# 2026-08-15 — RISC 리프터 x86-exact 32비트 의미론 (zero-extension + shift-count masking)

> 대상: `vm-obf` repo · node `ujiwo-zyris-code` (Windows) · branch `main`
> 작업일: 2026-08-15

## 요청
`src/vm/risc/` RISC 리프터+참조 시뮬레이터에 남은 두 가지 32비트 의미론 갭을 해결:

1. **32비트 레지스터 쓰기 zero-extension** — 32비트 GPR(EAX..R15D)을 쓰는 모든 x86 명령어는
   64비트 레지스터 상위 32비트를 0으로 만들어야 한다 (예: `add eax, ebx` → RAX 상위 32비트 = 0).
2. **32비트 시프트 횟수 마스크** — 32비트 시프트는 횟수를 mod 32(31 마스크)로 제한
   (`shl eax, 32` ≡ `shl eax, 0`), 64비트는 mod 64(63).

기존 12-op 원시 ISA를 유지하고, `eval_state`·폴리모픽 해석기·네이티브 threaded 하네스가 모두
동일 의미론을 갖도록 하는 것이 요구였다.

## 접근
변경을 **`src/vm/risc/lifter.rs`에만** 국한했다. 두 의미론 모두 마이크로-연산 스트림에 인코딩하므로
세 실행 계층(참조 시뮬레이터 / 폴리 해석기 / 네이티브 하네스)이 그대로 같은 의미론을 실행한다
(ISA/opcodes·`eval_state`·poly·threaded 비접촉).

- **zero-extension**: `RiscLifter::zero_extend_dst_if32(inst, dst)` 헬퍼 신설 — op0 레지스터가
  32비트면 디서인시스 결과 `dst`를 `AND dst, 0xFFFFFFFF`(기존 `emit_and`)로 마스크.
  적용 지점: `lift_binary_alu`(레지스터 목적지), `lift_shift`(레지스터 목적지),
  `Mov_r32_*`/`Mov_rm32_r32`(레지스터-레지스터), `Mov_r32_imm32`, `Neg_rm32`/`Not_rm32`,
  `lift_movsx`(Movsx_r32_*/Movsxd_r32_*). 메모리 목적지는 `MemoryWrite{width}`가 이미 절단하므로 불필요.
- **shift-count masking**: `lift_shift`가 `_rm32_` 계열 코드(`Shl/Shr/Sar_rm32_*`)를 감지해
  `is32` 판정. 즉시 카운트는 리프트 시점에 `& 31`, CL 레지스터 카운트는 `emit_and(Temp(2), cnt, 31)`로
  마스크 후 사용. 64비트는 기존 `& 63`(eval_state)에 위임.
- MOVZX는 이미 0-확장(AND 마스크)이라 추가 처리 불필요.

## 변경 파일
- `src/vm/risc/lifter.rs` — zero-extension 헬퍼 + 시프트 마스크 + 각 32비트 목적지 쓰기 지점 적용,
