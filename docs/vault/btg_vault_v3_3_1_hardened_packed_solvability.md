# BTG Vault V3.3.1 "Hardened" — 패킹된 exe 만으로 풀리는가? (분석 보고서)

> 작성: 2026-08-17 · 대상: `btg_vault_v3_3_hardened` 소스를 빌드 → `btg-packer`로 패킹한 `snaky.exe`
> 명령: `btg-packer.exe -i input.exe -o snaky.exe -l 3 -a --vm --vm-oep --vm-commercial --m8`

---

## 한 줄 결론

**수학적으로는 풀린다(가역 변환 + 41바이트 CIPHER가 바이너리에 실려 있음) — 그러나 "패킹된 exe 만"으로는**
**정적 분석만으로는 플래그를 복구할 수 없고, 동적 분석은 안티디버그(ud2 트랩)를 먼저 뚫어야 한다.**
즉, **의도된 난이도가 확실히 적용된 풀리는 크랙미**이며, 초심자 정적/문자열/XOR 스캔으로는 답이 안 나온다.

## 3. 정적 분석 (파일만으로) — **플래그 복구 불가**

패킹된 `snaky.exe`에서 확인된 것들:

| 재료 | 위치/상태 | 비고 |
|---|---|---|
| `CIPHER[41]` (="암호화된 플래그") | **평문, `.rdata` @0x14fb0** (언팩과 동일) | 데이터 섹션은 암호화 안 함 → 직접 읽힘 |
| `ADD[8]` 테이블 | **평문, `.rdata` @0x15012** | `2B 37 5D 11 83 45 99 77` |
| 키스트림 알고리즘 + `KS_MUL` `KS_ADD` | **네이티브 핸들러로 평문 노출** (`.textb` @0x3a5e6/0x3a5f7) | `movabs rax,0x5851F42D4C957F2D; imul ...; add; (st>>24)^(st>>8)^st` 로직 그대로 |
| **시드 `KS0`** (`0x243F6A8885A308D3`) | **바이너리 어디에도 없음** (LE/BE/32비트 절반 전부 탐색) | at-rest 암호화된 VM 바이트코드 내부에만 존재 |
| `ROT[8]` 스케줄 | 테이블로는 없음 (코드 즉치/VM 내부) | |
| 플래그 평문 | 없음 | |

**결론(정적):** 41바이트 `CIPHER`와 `ADD` 테이블, 키스트림 알고리즘, 그리고 상수 2개(KS_MUL/KS_ADD)는 파일에서 얻을 수 있지만, **가역 연산의 시드 `KS0`이 파일에 없어 역산할 수 없다.** 알려진 플래그 접두사 `BTG3{`(5바이트)만으로는 64비트 시드를 복구 불가(5~6바이트 키스트림 < 64비트 정보). → **파일 바이트만으로는 플래그를 못 뽑는다.**

> ⚠️ **설계 약점(참고):** `KS0 = 0x243F6A8885A308D3`은 **π의 소수부 16진수 / Blowfish 상수**로 알려진 공개 상수다. 키스트림 알고리즘(KS_MUL/KS_ADD 핸들러)이 평문으로 새어 있으므로, 이 상수를 알아보는 고수는 시드를 외워 넣고 **완전 정적 해법**을 만들 수 있다. 이는 바이너리 자체의 누출은 아니지만 보호 강도를 약화시키는 지점이다.

## 4. 동적 분석 (실행/디버깅) — cdb 실측

`cdb`(Windbg)로 `snaky.exe`를 실행해 확인:

| 시도 | 결과 |
|---|---|
| 디버거 하에서 그냥 실행 | **`0xC000001D` Illegal instruction 트랩** — `snaky+0x46d45`에서 `ud2` (엔트리 스텁 0x46d00 직후 +0x45 지점) |
| `ud2`를 NOP로 패치하고 진입점에 브레이크포인트 설치 | **실패** — `Win32 error 299`(ReadProcessMemory/WriteProcessMemory 부분 완료) → **안티디버그가 디버거의 메모리 쓰기까지 차단** |
| 디버거 없이 실행 | 정상 동작 (granted/denied) |

→ **패커의 안티디버그가 디버거 존재를 감지하면 엔트리에서 즉시 `ud2`로 죽인다.** 나이브하게 붙이는 디버거는 입력을 받기도 전에 프로세스가 종료된다.

**결론(동적):** 원리적으로는 풀린다. 런타임에 at-rest 암호화가 풀리므로 키스트림/시드가 메모리에 드러나고, `CIPHER`(평문)에 역변환을 적용하면 플래그를 얻을 수 있다. 하지만 실제로는 **① 안티디버그 우회 → ② VM 바이트코드 역분석/트레이싱으로 키스트림 복원 → ③ CIPHER 역산** 순서로 진행해야 한다. 초심자 수준이 아니다.

- 참고: 쉬운 "최종 비교를 패치해 Access granted 강제" 트릭은 **"Access granted."라는 문자열만** 얻을 뿐, **플래그 자체는 얻지 못한다** (프로그램은 플래그 평문을 메모리에 만들어 두지 않고, 오직 CIPHER + 변환만 가짐).

## 5. 최종 답변: 패킹된 exe 만으로 풀리나?

| 경로 | 플래그 복구 가능? | 난이도 |
|---|---|---|
| 정적 분석 (파일만) | ❌ 불가 (시드 `KS0` 누락) | — |
| 정적 + 상수 인지(π 상수) | ⚠️ 가능하나 파일 밖 지식 필요 | 고수만 |
| 동적 (디버깅) | ✅ 가능 | 높음 (안티디버그 우회 + VM 역분석) |
| 분기 패치 (Access granted) | ❌ 플래그는 못 얻음 | 낮음 |

**결론:** **풀리긴 풀린다(의도된 "solvable" 설계).** 하지만 "패킹된 exe 만"으로는
**정적으로는 답을 못 내고, 동적으로는 안티디버그와 VM을 뚫는 실력 있는 리버서만** 역산 키스트림으로 플래그를 뽑아낼 수 있다.
이는 구버전 v3.3(일방향 해시, 동적에도 플래그 불가) 대비 **의미 있는 진전** — 난이도가 실제로 보호 장치들로부터 나온다.
